MiniRSS 1.3.0 — компактная RSS-читалка для Windows 10 и Windows 11

ЧТО НОВОГО В 1.3.0
- Полностью обновлён интерфейс в духе Windows 11 / Fluent UI: светлые панели,
  спокойные цвета, крупные отступы, системный шрифт Segoe UI и иконки MDL2.
- Главные действия представлены иконками без длинных надписей; подсказки
  появляются при наведении мыши.
- Левая панель навигации: все новости, избранное, каталог RSS-источников,
  добавление ленты и настройки.
- Новая иконка MiniRSS для EXE и окна.
- Автоматическое обновление через публичные GitHub Releases.
- Сборка релизов автоматизирована через GitHub Actions при отправке тега vX.Y.Z.
- Пакет обновления проверяется по SHA-256; подписки, избранное и настройки
  сохраняются при замене EXE.

ОСНОВНЫЕ ВОЗМОЖНОСТИ
- Поддержка RSS 2.0, RSS 1.0/RDF и Atom.
- Добавление RSS/Atom-ссылок и готовые источники: Казахстан, Алматы,
  русскоязычные новости, мир, технологии, наука и космос.
- Общая лента, фильтр по источнику, поиск и избранное.
- Краткое описание публикации и открытие статьи в браузере.
- Автообновление лент каждые 15 минут.
- Компактное окно, режим поверх остальных окон, прозрачность 60–100%.
- Светлая и тёмная темы.
- Системный трей, автозапуск Windows и уведомления о новых публикациях.

БЫСТРЫЙ СТАРТ — СОБРАТЬ EXE ЛОКАЛЬНО
1. Установите Python 3.10 или новее с https://www.python.org/downloads/windows/.
2. При установке включите Add Python to PATH.
3. Распакуйте проект в обычную пользовательскую папку, например:
   %LOCALAPPDATA%\Programs\MiniRSS
4. Запустите build_exe.bat.
5. Готовый файл появится в dist\MiniRSS.exe.

ПОДКЛЮЧЕНИЕ GITHUB-ОБНОВЛЕНИЙ
Нужен публичный репозиторий GitHub. Приложение использует GitHub Releases API,
поэтому токен и отдельный сервер обновлений не требуются.

1. Создайте на GitHub новый публичный репозиторий, например minirss.
2. Загрузите в репозиторий всё содержимое этой папки проекта. В корне должны
   лежать mini_rss.py, build_exe.bat, requirements.txt, README.txt, assets/,
   tests/ и .github/workflows/publish-release.yml.
3. Откройте MiniRSS и перейдите в Настройки → Обновления через GitHub.
4. Введите адрес репозитория в формате владелец/название, например:
   myusername/minirss
5. Сохраните настройки. После появления первого GitHub Release приложение
   сможет проверять обновления вручную или автоматически раз в сутки.

КАК ВЫПУСКАТЬ НОВУЮ ВЕРСИЮ ЧЕРЕЗ GITHUB
1. В mini_rss.py измените APP_VERSION, например на 1.3.1.
2. Зафиксируйте изменения и отправьте их в основную ветку репозитория.
3. Создайте тег, совпадающий с номером версии:
   git tag v1.3.1
   git push origin v1.3.1
4. GitHub Actions автоматически запустит Windows runner, установит Python и
   зависимости, выполнит unit-тесты, соберёт MiniRSS.exe и подготовит архив.
5. Workflow создаст GitHub Release с двумя файлами:
   MiniRSS_1.3.1_win64.zip
   MiniRSS_1.3.1_win64.zip.sha256
6. Приложение увидит новую версию при следующей проверке обновлений.

Важно: тег и APP_VERSION должны совпадать. Workflow завершится ошибкой, если
тег v1.3.1 отправлен, а в коде всё ещё указана версия 1.3.0.

ПЕРВЫЙ ЗАПУСК И НАСТРОЙКА АВТООБНОВЛЕНИЯ
- Введите публичный GitHub repo как owner/name (или полный URL github.com/owner/name).
- Включите автоматическую проверку обновлений.
- При появлении новой версии MiniRSS покажет предложение установить релиз.
- Пакет скачивается только по HTTPS. До установки сверяется SHA-256.
- Установщик обновления делает резервную копию EXE, заменяет приложение,
  запускает новую версию и восстанавливает исходный EXE при ошибке.
- Сами RSS-подписки, избранное, настройки и история хранятся отдельно в
  %APPDATA%\MiniRSS и не входят в пакет обновления.

ПУБЛИКАЦИЯ ПЕРВОГО РЕЛИЗА
Для первого релиза, например v1.3.0, используйте те же действия:
  git add .
  git commit -m "MiniRSS 1.3.0"
  git push origin main
  git tag v1.3.0
  git push origin v1.3.0
Если ваша основная ветка называется master, замените main на master.
После завершения GitHub Actions откройте вкладку Releases и убедитесь, что
архив и SHA-256 файл опубликованы.

КАК СОХРАНЯЮТСЯ ДАННЫЕ
%APPDATA%\MiniRSS\feeds.json       — подписки и состояние RSS-лент
%APPDATA%\MiniRSS\favorites.json   — избранные статьи
%APPDATA%\MiniRSS\settings.json    — тема, прозрачность, трей, уведомления,
                                      автозапуск и GitHub-репозиторий обновлений

ПРИМЕЧАНИЯ
- Для новостей и проверки GitHub Releases требуется интернет.
- Автообновление работает с публичными GitHub-репозиториями и опубликованными
  Releases. Черновые релизы и приватные репозитории не поддерживаются.
- GitHub API может ограничивать частые запросы; поэтому по умолчанию проверка
  запускается не чаще одного раза в сутки.
- Если EXE лежит в Program Files или другой защищённой папке, Windows может
  запретить замену файла. Для удобного обновления храните его в папке
  пользователя, например %LOCALAPPDATA%\Programs\MiniRSS.
- Самостоятельная сборка EXE выполняется на Windows; в текущем окружении
  собраны исходники и GitHub workflow, но не Windows-бинарник.
